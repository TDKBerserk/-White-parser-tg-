# White-parser-tg

Парсер VPN-конфигов из Telegram-каналов с делением на белый и чёрный список по связке **IP-префикс + SNI**.

## Как это работает

1. **channels.txt** — список Telegram-каналов. Парсер заходит на `https://t.me/s/<channel>` каждого канала и вытаскивает:
   - прямые ключи (`vless://`, `trojan://`, `ss://`, `vmess://`);
   - ссылки на подписки (http/https) — скачиваются и тоже разбираются на ключи.
2. Каждый ключ проверяется на живость через HTTP GET к `host:port`.
3. Живые ключи резолвятся в IP, у них извлекается SNI (параметр `sni`/`host` в конфиге, либо сам домен, если используется вместо IP), и сверяются с белым списком:
   - **Белый** — первые два октета IP входят в `whitelist_ip_prefixes.txt` **И** SNI входит в `whitelist_sni.txt` (оба условия одновременно);
   - **Чёрный** — всё остальное.
4. Конфиги из **прошлого запуска** (`output/all_configs.txt`) подмешиваются в новую проверку — если источники временно недоступны, рабочие конфиги не теряются между циклами.
5. Рабочим конфигам меняется тег на `<Категория> | <Страна> | White-parser-tg`.

## Источник белого списка

`whitelist_ip_prefixes.txt` и `whitelist_sni.txt` генерируются `update_whitelist_ranges.py` на основе открытого проекта [RKPchannel/RKP_bypass_configs](https://github.com/RKPchannel/RKP_bypass_configs):
- `ip_list.txt` — первые два октета IP-диапазонов, которые реально пропускаются в режиме ограниченного интернета;
- `sni_list.txt` — домены (SNI), которые тоже пропускаются в этом режиме.

Такая связка (IP-префикс + SNI одновременно) точнее, чем привязка к спискам конкретных сервисов (Яндекс/ВК и т.д.) — она отражает, что реально проходит через ограничения, а не то, кому официально принадлежит IP.

Домены сервисов без записи в готовых списках (например, MAX) можно добавить вручную в `whitelist_domains.txt`:
```
# Название сервиса
domain1.example
domain2.example
```
Они попадут в SNI-список как есть, а их резолвленные IP — как префиксы.

## Файлы

- `channels.txt` — каналы-источники (по одному имени на строку, без `@`).
- `whitelist_domains.txt` *(опционально)* — доп. домены для сервисов без готовых списков.
- `whitelist_ip_prefixes.txt`, `whitelist_sni.txt` — автогенерируются, вручную не редактировать.
- `update_whitelist_ranges.py` — тянет `ip_list.txt`/`sni_list.txt` из RKPchannel + резолвит доп. домены.
- `collector.py` — сбор, проверка и классификация конфигов.
- `.github/workflows/update.yml` — почасовой запуск, коммитит whitelist-файлы и `output/`.

## Результат (`output/`)

- `white_configs.txt`, `black_configs.txt` — переименованные рабочие конфиги;
- `all_configs.txt` — «сырые» ключи без переименования (используются для carry-over между запусками);
- `white_base64.txt`, `black_base64.txt` — те же списки в base64 (подписка для клиентов);
- `summary.json` — статистика последнего запуска.

## Запуск вручную

```bash
pip install -r requirements.txt
python update_whitelist_ranges.py
python collector.py
```

## Важный нюанс

Даже точное совпадение IP-префикса и SNI со списками не гарантирует 100% работоспособность у конкретного оператора/вышки — финальное решение всё равно принимается по факту ответа на HTTP GET в `collector.py`. Списки `ip_list.txt`/`sni_list.txt` время от времени обновляются автором RKPchannel вручную — наш `update_whitelist_ranges.py` подтягивает актуальную версию при каждом запуске.
